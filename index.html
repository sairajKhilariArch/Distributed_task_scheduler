01 / Architecture

Three components. One task workflow.

The master coordinates the system, workers perform asynchronous task execution, and the client CLI gives users a simple way to submit work and inspect statuses.

⌘

Master node

Coordinates the task queue and task distribution, handles worker registration, and monitors worker heartbeats.

⇄

Worker nodes

Register with the master, periodically send heartbeats, poll for pending tasks, execute tasks asynchronously, and report results.

>_

Client CLI

Submit new tasks from the command line and list tasks to inspect their current statuses.

⚡

Async execution

Built with Tokio to support asynchronous work across the master and worker processes.

↔

HTTP communication

Axum provides the server-side HTTP API, while Reqwest is used for HTTP requests from clients and workers.

02 / Getting started

Build it. Start the master. Add workers.

Run each service in its own terminal. Start the master first, then launch one or more workers that point to the master's URL. Use the client CLI to submit tasks and list their statuses.

01

Build the project

Compile the project in release mode before running the services.

02

Run the master node

Start the master on port 8080. Keep this process running while workers connect.

03

Run worker node(s)

Open separate terminals for workers. Give each worker a unique ID and the master's address.

04

Submit and inspect tasks

Use the client CLI to submit a sample Fibonacci task or list all tasks and their statuses.

TERMINAL 01 · BUILD + MASTER
# Build the project
cargo build --release

# Run the master node
cargo run --bin master -- --port 8080
TERMINALS 02+ · WORKERS
# Run each worker in a separate terminal
cargo run --bin worker -- --worker-id worker-1 --master http://127.0.0.1:8080

cargo run --bin worker -- --worker-id worker-2 --master http://127.0.0.1:8080
CLIENT CLI · SUBMIT + LIST
# Submit a task
cargo run --bin client -- submit "Compute Fibonacci of 40"

# List all tasks and their statuses
cargo run --bin client -- list
